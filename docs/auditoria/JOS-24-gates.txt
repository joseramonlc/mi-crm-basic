INCIDENCIA en la primera ejecución:

Causa: el proyecto vive en /mnt/c dentro de Dropbox; la sincronización mantenía
abiertos ficheros de .next. NO es un error de código. Se resolvió con `rm -rf .next`

AVISO METODOLÓGICO: la primera ejecución se lanzó como `npm run build 2>&1 | tail -20`
y el runner informó "exit code 0" PESE A HABER FALLADO, porque en una tubería el código
recogido es el de `tail`, no el del build. Es el mismo patrón de verde falso que
JOS-23-gates.txt documentó para vitest. Las ejecuciones posteriores capturan el código
real con `npm run build > fichero 2>&1; echo "EXIT_REAL=$?"`.

Ejecución válida: EXIT_REAL=0

    el departamento de auditoría en JOS-21: "solo lo puede hacer una persona con
    navegador y sesión iniciada".

backend y UI, y el gate quedó descolgado. Es un fallo de diseño del plan, no del código.

bocado B, con el mismo escenario y las mismas cifras de contraste. Guión completo en
docs/auditoria/JOS-24-e2e.md, con la parte no autenticada ya ejecutada (§1).
